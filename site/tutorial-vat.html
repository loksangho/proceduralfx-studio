Vertex animation for 3D games

Tutorial 4 · about 15 minutes

Coming in the next update: Export Vertex Animation isn't in version 0.20.0 yet.

Simulations are too slow to run in a game, so you bake them. A vertex animation texture (VAT) stores every frame of an effect's motion in a texture. A small shader in the game reads it and moves the mesh on the GPU. It's how games use cloth, destruction and splashes from Houdini, and it costs about one texture read per vertex.

The three kinds

  • Soft: a mesh whose points stay the same and move freely, like cloth, deformers, or wobbling and twisting shapes.
  • Rigid: pieces that move and turn without bending, like destruction and RBD. Each piece's position and rotation is stored, so pieces never warp.
  • Fluid: a mesh whose points and polygons change every frame, like a liquid from Particle Fluid Surface. Every triangle corner is stored, so the textures get large. Keep the surface's resolution modest.

You don't have to choose: Automatic picks the kind that suits the motion.

1. Make something that moves

Any animated geometry object works. Two quick ones:

  • Wobble (soft): the scene the app opens with already moves. Its noise node changes over time. Press Space to see it.
  • Destruction (rigid): in a geometry object, wire a box into a xform (Transform) to lift it up, then into a material_fracture to break it, then into an rbd_solver to drop it. Double-click the RBD solver to show it, and press Space.

Set the timeline's Start and End to the frames you want to bake.

2. Bake it

  1. Choose Render → Export Vertex Animation….
  2. Pick the Object. It starts on the one you're looking at.
  3. Leave Kind on Automatic. Under Frames, baking every second frame halves the textures. The game blends between frames anyway, except for fluids.
  4. Tick Godot or Unity under Also for, click Export…, and save into your game's project. The status bar shows the bake's progress, and which kind it chose.

You get name.obj (the mesh), two EXR textures (the motion), and name.vat.json describing them, plus the engine's shader and material.

3a. Play it in Godot 4

  1. Add a MeshInstance3D and drag name.obj onto its Mesh.
  2. Drag name_vat_material.tres onto its Material Override.
  3. Run the scene: it plays and loops by itself. To control it from a script, turn off the material's use_time and set frame.

The export includes import settings that stop Godot compressing the textures and mesh, which would ruin the numbers. Keep the .import files with them.

3b. Play it in Unity (URP)

  1. Export into your project's Assets folder. The .meta files beside the textures keep them exact.
  2. Drag name.obj into the scene, and drag name_vat.mat onto it.
  3. Press Play. Untick Play by itself on the material to set the frame yourself.

Your project must use the Linear colour space, which is URP's default. In Gamma, Unity changes the textures' numbers, and the shader shows the mesh in magenta rather than move it wrongly. Change it in Project Settings → Player → Other Settings → Color Space.

Tips

  • If the mesh vanishes when pieces or splashes fly far from where they started, the engine thinks it's off screen. The JSON's bounds give the whole animation's size. Set Godot's Extra Cull Margin (or Custom AABB), or Unity's Renderer.localBounds, to cover it.
  • If the bake says the geometry changes part-way through, its points or polygons aren't the same every frame. Choose Fluid, which allows that.
  • From a terminal: proceduralfx_studio vat scene.pfs out/name --godot --unity bakes without opening the app. Add --mode rigid to choose the kind.
